# 工具组合手册（组合思维：把 50 个工具串成解决方案）

> 本册管「**编排**」——遇到多步任务怎么选工具、排顺序、验产物、防烂尾。
> 各工具的参数细节在对应分册（word文档/表格/ppt文档/论文排版/图片视频/网络下载/跨设备协作），本册只讲怎么串。

## 一、核心心法：用户给的是目标，不是步骤

用户说"做一份重庆介绍 PPT"，脑子里想的是**一份能直接用的 PPT**，不是"你自己编点内容凑数"。因此：

1. **先拆解**：目标 = 内容（哪来的？）+ 素材（图哪来的？）+ 产出（什么格式？放哪？）
2. **再选链**：内容靠 `web_search + web_fetch`（禁止编造事实），图靠 `generate_image + download_file`，产出靠 `create_pptx/create_word`
3. **排顺序**：每一步的输出是下一步的输入（抓回来的资料喂给生成、下回来的图插进文档）
4. **验产物**：每步确认产物真实存在（文件返回了路径、图片返回了 URL/路径）才进下一步——**链上任何一步产物缺失，继续往下走就是烂尾**

## 二、组合公式库（对号入座，按需变形）

| 场景触发词 | 工具链（按序） | 关键点 |
|---|---|---|
| 做介绍/调研 PPT、报告 | web_search → web_fetch(text) → generate_image/download_file → create_pptx/create_word | 事实全部来自抓取，生成图注明"示意图"；PPT 大纲先给用户过一眼再成稿更好 |
| 收集图片素材 | web_search → web_fetch(mode:"images") → download_file 批量并行 | download_file 一轮可发多个并行；防盗链传 referer=来源页 |
| 数据 → 图表 → 报告 | read_table → （分析）→ 手写 SVG 存文件 → svg_to_png → create_word/create_pptx 插图 | 图表先 view_image 自检再看，坐标轴别重叠 |
| 扫描件/图片型 PDF 转文字 | read_pdf（报"没有文本层"）→ pdf_to_image → view_image 逐张转录 → create_word 汇总 | 逐页转录，别一次啃 10 页糊成幻觉 |
| 论文排版 | read_paper_spec → apply_word_template → check_paper_format → 循环修 → fix_paper_paging | 完整闭环规则见「论文排版.md」，本册不重复 |
| 桌面/文件夹大扫除 | screenshot（看现状）→ list_dir + search_files（摸清家底）→ create_folder → move_path 批量归类 | move 支持数组批量，一类一批；删除类操作快照可还原，但先跟用户确认口径 |
| 帮朋友电脑找文件/传东西 | transfer_file（双向）+ list_dir/read_file(target:设备) | 远程路径永远先 list_dir 探真实路径，禁止猜；详见「跨设备协作.md」 |
| 屏幕报错/界面答疑 | screenshot(scope:"screen") → view_image → 给方案 | 截完图才能看内容，禁止空想屏幕上有什么 |
| 多角度对比调研 | delegate ×4 并行子 Agent（每个子任务自包含）→ 主会话汇总 → create_table/create_word 出对比 | 子任务描述必须自包含（子 Agent 看不到你们的对话） |
| 改既有文档小字 | read_word/read_pptx 定位 → modify_word(edit)/edit_pptx 精准替换 | 只改字不动版式；大改直接重建 |
| 压缩包内容处理 | zip_extract → 逐文件处理（read/view/edit）→ zip_compress 回包 | 中间产物放工作区子文件夹，别散落桌面 |

## 三、完整实战示例

### 示例 1：「下载重庆的图片和收集重庆信息，做一份重庆介绍 PPT」

用户原话就这一句。标准执行序列：

```
① task_plan 建清单：[搜资料 → 抓正文 → 备图 → 定大纲 → 出 PPT → 交付]
② web_search("重庆 旅游 攻略|重庆 城市 简介|重庆 美食 景点")   ← 一次传 2-3 个不同角度
③ web_fetch(搜到的 2-3 篇优质正文, mode:"text")                ← 事实底稿：地理/景点/美食/交通
④ 图分两路并行：
   download_file(精选实景图直链 ×3-5, save_path:工作区\重庆ppt\图)   ← 真实照片
   generate_image("重庆洪崖洞夜景，赛博朋克风城市插画") ×1-2           ← 补风格化示意图
⑤ view_image 检查下载的图（确认没下错、没糊）
⑥ 大纲先给用户过目（一句"我打算这样分 8 页：封面/简介/洪崖洞/美食/交通/总结，可以吗"
   ——或直接产出，视用户语气急缓）
⑦ create_pptx(path:桌面\重庆介绍.pptx, title:"重庆", content:
   "theme: 山城霓虹\nstyle: sharp\n---\n#cover 重庆·山水之城\n---\n## 城市名片 ..." 
   ← 每页配图路径填真实产物路径，写法详见「ppt文档.md」）
⑧ 交付前自检：文件存在 + 报告路径；提醒"图 X 为 AI 示意图"
```

**错误示范（禁止）**：跳过 ②③ 直接凭记忆写"重庆有长江三峡、火锅很好吃"——数据可能过时/错误；跳过 ⑤ 直接插图——下载失败也会被写进 PPT。

### 示例 2：「这份 PDF 是扫描件，帮我转成 Word」

```
① read_pdf(报错返回"没有文本层") → 立刻转策略：pdf_to_image(path, pages:"1-8")
② 对每张 PNG：view_image(path, question:"完整转录图中文字")   ← 逐页来，禁止合并转录
③ create_word(path:同名.docx, content: 按页序拼好的转录稿 + 页码标注)
④ 交付时说明：第 N 页原稿有涂改/印章无法辨识的部分已标「[手写/模糊]」
```

### 示例 3：「我桌面乱死了，帮我整理」

```
① screenshot(scope:"screen") 看桌面实际布局 → view_image 确认
② list_dir(桌面) 拿完整清单 → 心里分类：图片/文档/压缩包/安装包/其他
③ create_folder(桌面\图片存档) 等 3-4 个目标夹
④ move_path(src:[一批同类的完整路径数组], dest_dir:对应夹)   ← 一类一批，禁止一锅端
⑤ 汇报归档结果表；提醒用户：全部可还原（快照在），"不满意说一声我撤"
```

## 四、组合铁律（违反=烂尾）

1. **每步验产物**：上一步没拿到真实路径/URL，下一步不许引用它。文件名永远用工具返回的，禁止脑补
2. **并行有度**：download_file 可一轮多个；delegate 最多 4 个；同域写操作（move/delete）串行
3. **失败自愈三连**：换关键词重搜 → 换引擎/换图站 → 降级方案（下不到实景就 generate_image 兜底并注明）。禁止一步失败就撂挑子，也禁止原地死磕超过 3 次
4. **素材诚实**：AI 生成图要向用户注明"示意图"；事实性内容必须有抓取来源，禁止编造数据（价格/日期/历史）
5. **交付自检**：写完 read 一眼确认内容完整；转完格式抽查首页；做完 PPT 报告文件绝对路径
6. **长任务挂清单**：≥3 步必须 task_plan，系统会把"下一步"提示附在结果里，照着走防跑偏
7. **分册优先**：进入 word/表格/ppt/论文/图片/联网/跨设备 任一具体域的参数细节，先 read_file 对应分册——本册只管串，参数看分册

## 五、真人式工作节奏（像真人助理，不像脚本）

复合任务全程按这个节奏走，用户随时知道"干到哪了、还差什么"：

```
【开工报目标】一句话说清要交付什么、几步、素材来源
   "好的，我来做一份 8 页的重庆介绍 PPT：资料从旅游攻略抓真实内容，
    配图用实景下载+2 张风格化示意图，做完放你桌面。开工 ↓"
【清单挂账】task_plan 建清单（每项一个具体动作）
【逐步推进 + 播报】每完成一项，一句话报进度，随即自动推进下一项：
   "✓ 资料抓完：3 篇攻略，提取了景点/美食/交通三块"
   "✓ 图片就位：4 张实景 + 1 张示意图（会标注 AI 生成）"
   "✓ 大纲定了：封面/名片/景点×2/美食/交通/总结，共 8 页"
   "⏳ 正在生成 PPT……"
【卡点求助】素材下不到/内容有分歧/路径拿不准 → 停下，说明卡在哪，
   给 2 个方案让用户挑（ask_user），别硬编也别静默放弃
【交付交代】收尾必给三件套：
   ① 产出文件完整路径（可点击打开）
   ② 一句总结（做了什么、数据/图来源）
   ③ 后续建议（"要改配色/加一页夜景图，说一声"）
```

反面教材（禁止）：闷头执行 8 个工具一步不吱声 → 最后甩一句"做完了"。用户全程不知道你干得对不对，错了也是 8 步之后才发现。
