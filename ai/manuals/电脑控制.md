# 电脑控制手册：网页填表 + 桌面键鼠（挂机办公）

两大能力域：**browser_***（AI 受控浏览器，网页填表首选）和 **desktop_***（真实键鼠，第三方程序用）。原则：**能走 browser_* 就不走 desktop_***——网页操作有结构化快照，比"截图猜坐标"稳十倍。

## 一、网页填表五件套（browser_*）

标准闭环：`navigate → snapshot → fill/click（循环）→ read 验证`

### browser_navigate(url)
在"AI 浏览"页签打开网页（用户全程可见，透明操作）。http/https 均可，不带协议自动补 https。等待加载完成后返回标题。

### browser_snapshot()
列出当前页面全部可交互元素，每行格式：

```
e3: input[type=text] 占位="手机号" 文="" @ (412,238 260x36)
e7: button 文="登 录" @ (412,420 260x44)
```

- **编号（e1/e2...）是后续 click/fill 的凭据**
- 页面一旦重渲染（点击提交、SPA 路由、弹窗），编号全部过期——**必须重新 snapshot**
- 元素超 120 个会截断：优先在 snapshot 前用 click 展开目标区域，或按位置判断元素大致范围

### browser_fill(ref, value)
向 input/textarea/select/contenteditable 填值。自动派发 input+change 事件（React/Vue 受控组件能感知）。

- select 下拉：value 匹配选项的 value **或**可见文本，任一命中即可
- 返回 `NOT_EDITABLE` = 该元素不可填（比如你选到了外层 div），重新 snapshot 找正确的 input
- 返回 `REF_GONE` = 编号过期，重新 snapshot

### browser_click(ref)
点击按钮/链接/复选框。派发完整鼠标事件序列（pointerdown→mousedown→up→click）+ 原生 click，兼容大多数框架。点击后等 600ms + 探测导航，返回当前页面标题帮你判断跳转结果。

### browser_read()
读页面正文（≤8000 字）+ 标题 + URL。**提交表单后必须 read 一次核对结果**（成功提示/报错文案都在正文里）。

### 典型填表流
```
1. browser_navigate url="https://example.com/login"
2. browser_snapshot
3. browser_fill ref=e3 value="13800000000"   ← 用户名
4. browser_fill ref=e5 value="密码123"        ← 密码框（type=password 会显示为占位）
5. browser_snapshot（确认值已填入，看 文= 字段）
6. browser_click ref=e7                      ← 登录按钮
7. browser_read                              ← 核对登录结果
```

## 二、桌面键鼠五件套（desktop_*）

操作**第三方程序**（计算器/微信/WPS 弹窗/无网页界面的一切）。

### 定位三板斧（desktop_click 前必做）

```
1. desktop_window action:"list"        ← 看有哪些窗口，拿到目标 pid
2. desktop_window action:"activate" pid=1234   ← 把目标窗口拉到前台
3. screenshot scope:"screen" → view_image 看屏 ← 让视觉模型输出目标坐标
```

**坐标两套传法（nx/ny 归一化优先，最准）**：

- **归一化坐标（推荐）**：view_image 提问时加一句 **"输出目标中心点归一化坐标(x,y)，范围 0-1000"**（如 `"输出"开始按钮`中心点归一化坐标(x,y)，0-1000"`）→ 模型返回如 `(512, 968)` → `desktop_click nx=512 ny=968`。视觉模型对"位置百分比"的判断远准于绝对像素，且不受截图缩放/DPI 干扰（Anthropic computer-use 同款协议）
- **绝对像素**：screenshot 返回会注明"图 X×Y = 屏幕物理分辨率 1:1"，图上看到的像素位置直接传 x/y。两个坐标系都通，**点歪了一次就换归一化重试**

### desktop_click(x, y, button?, double?, hold_keys?)
单击/双击/右键/中键。`hold_keys:["ctrl"]` = 按住修饰键点击（多选文件、框选场景）。点完目标程序有反应后，**再截屏一次确认效果**。

### desktop_type(text)
向当前焦点窗口逐字输入（支持中文，UNICODE 逐字符注入）。前提：输入框已获得焦点（先 click 输入框）。

### desktop_key(keys)
组合键数组，修饰键在前主键在后：`["ctrl","s"]` 保存、`["enter"]` 确认、`["alt","f4"]` 关窗口、`["ctrl","shift","esc"]` 任务管理器。支持 f1-f24/字母/数字/方向键/backspace/delete/home/end/pageup/pagedown/esc/tab/space。

### desktop_scroll(x, y, amount, horizontal?)
指定位置滚轮：正数向上、负数向下（一格≈120）。`horizontal:true` 走横向滚轮（宽表格/时间轴）。翻长列表用。

### desktop_drag(x1, y1, x2, y2, steps?, hold_keys?)
鼠标拖拽：起点按下左键 → 平滑移动到终点 → 松开。适用：**拖文件到文件夹、拖滑块调音量/进度、选中一段文字、框选元素、移动窗口位置**。起点终点都支持 nx/ny 归一化（nx1/ny1/nx2/ny2）。`hold_keys:["shift"]` = 按住 shift 拖（多选框选）。拖完截屏确认效果。

### desktop_move(x, y / nx, ny)
移动鼠标到指定位置（**不点击**）：悬停显示 tooltip、展开悬停菜单。悬停才出现的内容先 move 过去再截图。

### desktop_window(action, pid?)
- `list`：列出全部可见窗口（pid + 进程名 + 标题）
- `activate`：拉到前台（**click/type 前必须激活**，否则点的是别的窗口）
- `minimize` / `maximize` / `close`：窗口管理（close 相当于点 X，走正常关闭流程）

### 典型挂机流
```
1. desktop_window action:"list"          ← 找到目标程序 pid
2. desktop_window action:"activate" pid=5678
3. screenshot scope:"screen" → view_image  ← 看清界面布局
4. desktop_click x=820 y=415              ← 点"新建"按钮
5. screenshot scope:"screen" → view_image  ← 确认弹出了输入框
6. desktop_click x=900 y=450              ← 点输入框获得焦点
7. desktop_type text="报销单-0721"          ← 输入文字
8. desktop_key keys=["ctrl","s"]          ← 保存
9. screenshot scope:"screen" → view_image  ← 最终确认
```

## 三、控制模式与安全红线

控制模式三档（Work 输入区右上角胶囊，点击切换）：

| 档位 | 行为 |
|---|---|
| 手动批准（黄） | desktop_* 每次操作都弹审批卡；browser_* 不弹（页签可见） |
| 自动信任（绿） | desktop_* 自动执行；C 盘保护区、exe/脚本打开仍弹卡 |
| 无限制（红） | 全部自动执行（含 exe/脚本）。**会话级档位**：开启需菜单内二次确认，重启应用自动回落自动信任 |

红线（无论什么档位都自觉遵守）：
1. **不碰支付/转账页面**：网上银行、支付确认、验证码输入，必须用户本人在场操作，AI 禁止代填
2. **删数据先问**：desktop_* 涉及删除文件、清空列表、发送消息给真人时，先向用户确认
3. **每次操作后截屏验证**：盲操作（不确认就连续点击）是挂机事故第一来源
4. **坐标来自截图而非记忆**：窗口位置会变，每轮操作前重新看屏

## 三·补、前台占用铁律（用户在办公时 AI 怎么干活）

单鼠标单键盘是物理事实：**desktop_* 接管键鼠期间，用户动鼠标/键盘必然和 AI 打架**——最坏情况 AI 的字灌进用户正在编辑的表格/文档。铁律：

1. **浏览器任务一律走 browser_* 五件套**（受控页签在工作台内后台执行，不碰真实键鼠，用户怎么办公都不受影响）："开浏览器打开某页填东西"="browser_navigate + snapshot + fill"，**禁止用 desktop_click 去点浏览器**。只有受控页签引擎跑不动的东西（桌面客户端、Flash 类页游、需要系统弹窗的场景）才允许 desktop_*
2. **desktop_* 开工前提醒**：第一次 desktop_* 调用前，用一句话告知用户"我将接管鼠标键盘，期间请勿操作（Ctrl+Shift+X 随时急停）"
3. **检测到用户占用立即停手**：键鼠操作返回"检测到鼠标正在移动（用户可能正在操作电脑）"时——说明用户在动鼠标。**禁止原样重试**：先 ask_user 问"您是不是在用电脑？我暂停等您空闲，还是继续？"；用户说继续才恢复操作
4. **AI 的操作落点即基线**：AI 自己点击/滚动后鼠标位置被系统记住，不会被误判为"用户在动"——放心连续操作，系统只在真人动鼠标时拦截

## 四、踩坑备忘

- browser_* 返回 REF_GONE：页面重渲染了，重新 snapshot（这不是故障是正常机制）
- desktop_type 中文丢字：目标窗口没焦点或还在加载，先 activate + 截屏确认再输
- 管理员权限窗口（UAC 弹窗/任务管理器）：受系统 UIPI 限制可能点不动，如实告知用户手动处理
- 网页里有 iframe：snapshot 只能看到主文档元素，iframe 内元素抓不到——改用 desktop_* 屏幕坐标方式操作
- 全屏游戏/远程桌面里坐标可能错位：截图分辨率 ≠ 屏幕物理分辨率时（缩放 125%/150%），以截图像素为准（screenshot 输出就是物理像素）

## 五、静默快跑模式（控制任务专用提速，必读）

desktop_* 操作循环是"截屏→决定→动手"多轮往返，**每一轮的正文解说和多轮思考都是纯耗时**（模型输出逐字蹦，100 字解说 ≈ 白等 3-5 秒）。控制任务全程遵守：

1. **循环期零解说**：desktop_click/type/key/scroll 的每一轮**只输出 tool 块，不写正文**（一句"好"都别写）；需要连续动作就顺次发多个 tool 块，最后一步干完才说话
2. **汇报只在收尾**：全部操作完成后一次性说清做了什么+结果；中途每步"已点击/已输入"的播报全部省略（工具返回本身就是进度）
3. **主模型用快的**：控制任务不需要深度思考——用非思考快模型（Flash 类），一轮推理几十秒→几秒；深度思考开着等于每步白等几十秒
4. **视觉提问要短**：view_image 的问题只问要什么（"输出开始按钮中心点归一化坐标(x,y)，0-1000"），别让它写小作文

速度账：静默+快模型后，单步 ≈2-4 秒；10 步任务从"几分钟"压到"半分钟内"。
